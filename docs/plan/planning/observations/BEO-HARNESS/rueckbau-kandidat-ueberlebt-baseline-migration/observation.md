# Rückbau-Kandidat überlebt Baseline-Migration statt aufgelöst zu werden

**Sub-Area:** Harness-Einstieg

Ein als „Rückbau-Kandidat" ausgewiesener Adaptions-Eintrag (Ersetzt-Baseline-Regel: keine, korrigiert
nur eine eigene Repo-Aussage) nennt als sauberen Auflösungs-Trigger die Überarbeitung von
[`MR-000`](../../../../../../harness/conventions.md#mr-000)s ID-Schema-Deklaration — und als
Ersatz-Trigger „die nächste Baseline-Migration". Zweimal in Folge griff nur der billigere
Ersatz-Trigger (reine Versionskorrektur,
[`MR-007`](../../../../../../harness/conventions.md#mr-007)→[`MR-013`](../../../../../../harness/conventions.md#mr-013),
[`MR-013`](../../../../../../harness/conventions.md#mr-013)→[`MR-017`](../../../../../../harness/conventions.md#mr-017));
die saubere Auflösung trat nicht ein.
